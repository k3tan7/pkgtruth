USER GUIDE & ONBOARDING

Welcome to pkgtruth

pkgtruth is a private, local cybersecurity intelligence platform that inspects Python packages before you install them. It helps you see what changed between reviewed source code and published wheel archives.

How to investigate a package

5 Steps
  1. Open Scan Package Navigate to Scan Package in the workspace sidebar.
  2. Find your package on PyPI Enter the exact name (e.g., idna, requests) to list published versions.
  3. Select a release version Choose the version you are evaluating and click Analyze Package.
  4. Read the 5-second summary Check the plain-English verdict, findings count, and recommended next steps at the top.
  5. Explore findings & technical diffs Review "What we found" cards and expand technical details to inspect file differences.

Decoding verdicts & coverage

Definitions
Supported checks completed

All supported static tests and file comparisons finished successfully. This does not guarantee the software is free from vulnerabilities or malicious logic.

Coverage needs review (PARTIAL)

Some checks could not be completed (e.g., source repository was unavailable, or files exceeded parsing bounds). Review the limitations section in the report.

Source correspondence

pkgtruth attempts to locate the upstream repository declared in package metadata. Finding a matching release tag is an unauthenticated claim by the publisher, not cryptographic provenance.

Wheel RECORD integrity

A valid RECORD file confirms internal package consistency—that files inside the wheel match the creator's manifest. It does not prove publisher authenticity.

Translating technical packaging terminology

Glossary
ARTIFACT_ONLY Present only in the published wheel
Files found inside the package that were not present in the compared source repository. May be compiled assets or unexpected additions.
SOURCE_ONLY Present only in the source repository
Files in git that were omitted from the wheel. Tests, docs, and CI configs are commonly omitted from built wheels to reduce download size.
RECORD mismatch Internal package digest mismatch
The cryptographic hash or size of a file does not match the manifest inside .dist-info/RECORD, indicating post-packaging corruption or tampering.
Startup directive (.pth) Automatic startup code execution
A .pth file containing import statements executes code as soon as Python initializes, before user code imports any module.

Platform Capabilities

Features
  • Compare Releases (Release DNA): Track how package capabilities evolved between two releases to spot newly introduced execution surfaces.
  • Watchlist: Track critical packages on PyPI and receive notice when newly published versions or changed distribution digests appear.
  • Security Rules: Define deterministic policies that flag packages for review or block installation when high-priority indicators occur.
  • Local AI Investigator: Ask local Qwen via Ollama to explain observed patterns without leaking package code or findings to external cloud services.
  • Proof Capsule: Export a standalone, self-contained, offline HTML report containing all verified findings and cryptographic hashes.

What pkgtruth cannot guarantee

Boundaries

pkgtruth provides grounded evidence to assist human security decisions. It is not an absolute oracle of safety:

  • Zero code execution: pkgtruth never executes or tests target packages at runtime. Dynamic behavior, memory safety issues, and network activity occurring during runtime execution cannot be observed.
  • Unauthenticated provenance: Matching GitHub tags are public declarations. Unless cryptographically signed with Sigstore or PEP 740 attestations, finding matching source does not prove git produced the wheel.
  • Parser resource bounds: Files exceeding size limits (e.g., 16 MiB archives, 128 KiB parser buffers) are bounded to prevent denial-of-service.
Always treat findings as verified evidence to guide an informed engineering choice, not as absolute proof of innocence or malicious activity.
